# SwagToVideo

Веб-приложение: пользователь загружает трек, добавляет текст песни — и получает видео-визуализацию
(измерители в духе MiniMeters, кинетическая типографика, акценты-эффекты на выбранных словах).
Основной формат — вертикальное видео 9:16 для соцсетей, формат/разрешение/fps настраиваются.

## Ключевые решения (не пересматривать без главной сессии)

- **Всё работает в браузере.** Сервера нет. Хостинг — Vercel Hobby (деплой из GitHub-репозитория).
- **Никаких внешних API-сервисов** (ни LLM, ни сервисов текстов песен, ни облачных GPU).
  npm-библиотеки, собранные в бандл, — можно.
- **Без Remotion.** Рендер-движок свой.
- **ML-модели — только в браузере** (ONNX через transformers.js / onnxruntime-web, WebGPU с WASM-фолбэком).
  Веса лежат в собственном публичном репозитории пользователя на Hugging Face (закреплённые копии),
  кэшируются в браузере (Cache API / OPFS), плюс импорт моделей из файла.
- **Проект некоммерческий**: модели под CC BY-NC допустимы. Код под AGPL в проект не копируем.
- Языки текстов: **RU и EN**.
- Целевой браузер: Chrome/Edge (WebCodecs, WebGPU). Остальные — через feature-detect и фолбэки.
- Vercel требует заголовки COOP/COEP (SharedArrayBuffer для многопоточного WASM) — задаются в `vercel.json`.

## Стек

Vite + React + TypeScript, Tailwind + shadcn/ui, Zustand · Web Audio API + Web Workers ·
WebGL2 / Three.js + GLSL, Canvas 2D · WebCodecs + mediabunny · transformers.js (Whisper), onnxruntime-web (HTDemucs).

## Архитектура в одной картинке

```
Трек ─► Аудио-анализ ─┐
Текст ─► ML + Лирика ─┼─► timeline.json ─► Рендер-движок ─► превью (realtime)
Акценты (UI) ─────────┘                         └──────────► Экспорт (offline, покадрово, WebCodecs)
```

`timeline.json` — единый контракт между частями: покадровые аудио-признаки, биты/onsets,
слова с таймкодами и уверенностью, акценты. Рендер детерминирован: превью = экспорт.

## Оркестрация сессий

Проект ведётся несколькими тематическими сессиями Claude. **Главная сессия** — координатор:
обсуждение проекта, архитектурные решения, контракты между модулями, git (commit/push в GitHub),
ревью и сведение работы тематических сессий.

| Сессия | Устав | Владеет |
|---|---|---|
| Аудио-анализ | `docs/sessions/audio-analysis.md` | `src/audio/` |
| ML и Hugging Face | `docs/sessions/ml-models.md` | `src/ml/`, `scripts/models/`, `models.json` |
| Текст и тайминги | `docs/sessions/lyrics-sync.md` | `src/lyrics/` |
| Рендер-движок и визуализация | `docs/sessions/render-engine.md` | `src/render/`, `src/visualizers/`, `src/effects/` |
| Фронтенд и UI | `docs/sessions/frontend-ui.md` | `src/app/`, `src/ui/`, стили |
| Экспорт видео | `docs/sessions/video-export.md` | `src/export/` |

Общие файлы — **`src/shared/`** (типы, схема `timeline.json`), `package.json`, `vite.config.ts`,
`vercel.json`, `CLAUDE.md`, `docs/` — принадлежат главной сессии.

### Правила для тематических сессий

1. Работай только в своих папках. Нужна правка чужой области или общего контракта — опиши её
   и передай главной сессии, сам не меняй.
2. **Не делай git commit/push, не создавай ветки** — это делает только главная сессия.
3. Новые npm-зависимости — только после согласования с главной сессией (проверка лицензии и веса).
4. Фундаментальные решения из списка выше не пересматривай самостоятельно — предлагай главной сессии.
5. Закончив кусок работы, кратко отчитайся: что сделано, какие файлы, что не проверено, что нужно от других.
6. Ничего не начинай без задачи от пользователя или главной сессии.
