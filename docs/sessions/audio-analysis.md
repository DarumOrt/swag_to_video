# Сессия: Аудио-анализ

**Владеет:** `src/audio/`

## Зона ответственности

Декодирование загруженного трека и расчёт всех аудио-признаков, которые нужны визуализации и
выравниванию текста. Всё — в браузере, в Web Worker, без внешних сервисов.

## Что должно получиться

- Декодирование (Web Audio `decodeAudioData` / `OfflineAudioContext`), моно/стерео, ресемплинг
  (в т.ч. 16 кГц моно для Whisper — отдаёт ML-сессии).
- **Покадровые признаки на фиксированной сетке `features.rate`** (не зависит от fps экспорта, см. `src/shared/timeline.ts`): спектр (FFT, лог-шкала по частотам, сглаживание),
  RMS / пики / LUFS (краткосрочная громкость), стерео-данные для гониометра и корреляции,
  энергии частотных полос (низ / середина / верх — «бочка / вокал / хэты»).
- **Ритм:** BPM, сетка битов, даунбиты, onsets (в т.ч. отдельная огибающая onsets вокальной полосы —
  её использует лирика для «магнита» слов).
- Детектор участков без вокала (по энергии вокальной полосы) — для пропуска проигрышей при распознавании.
- «Вокальный фокус» (mid-канал + полоса ~120 Гц–6 кГц + компрессия) как дешёвая предобработка для Whisper.
- Данные пишутся в аудио-часть `timeline.json` (схема — в `src/shared/`, правки схемы через главную сессию).

## Требования

- Детерминизм: один и тот же трек → одни и те же числа (важно для покадрового экспорта).
- Не блокировать UI: тяжёлое — в воркере, прогресс наружу.
- Компактное хранение (typed arrays, при необходимости квантование), длинные треки не должны съедать память.

## Связи

- **Рендер-движок** — главный потребитель покадровых признаков.
- **ML / Лирика** — 16 кГц аудио, вокальный фокус, onsets вокала, участки без вокала.
- **Экспорт** — тот же декодированный звук для мукса.
